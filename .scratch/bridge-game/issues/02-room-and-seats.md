# 02：通过浏览器创建房间、加入与选座

Status: ready-for-agent

Blocked by: 无，可立即开始

**交付行为：** 玩家通过局域网浏览器以昵称创建或加入独立房间，并实时看到座位与房主。

## 验收标准

- [ ] 建立可在 macOS 开发运行的 React、TypeScript、Vite、Fastify、Socket.IO 与 SQLite 应用，页面和资源由同一服务提供。
- [ ] 创建房间返回房间码；使用房间码加入，拒绝同房间重复昵称、无效房间及已占座位；房主与加入顺序明确可见。
- [ ] 服务端发放不可猜测的持久身份凭据，同一浏览器刷新可恢复身份和座位，不能凭昵称或连接标识冒用身份。
- [ ] 两个浏览器可实时看到东南西北座位变化；不同房间的身份、状态和操作隔离，服务端校验每次操作权限。
- [ ] 房间与身份写入真实 SQLite，成功提交后才确认和广播；建立操作标识、状态版本及明确错误响应的公共行为。
- [ ] 通过对局应用服务入口测试建房、入房、选座和授权，并用浏览器走通首条流程；移动视口无关键控件遮挡。

## 依据与实施约束

- [正式规格](../spec.md)。验收覆盖：T04、T12、T15、T21、T23 的房间部分。
- 使用项目领域术语与已确认架构；每项涉及的操作都需服务端授权、按房间顺序处理、版本与重复操作校验，并在持久化成功后确认和广播。
- 以对局应用服务公开行为为主要测试入口，按需使用可控发牌、时钟和真实临时 SQLite；关键浏览器流程随本票验证。
- 界面参考用户提供的 [Open Design 参考稿](../../../design/references_classic.html)：以柔和绿牌桌、清晰座位方位、手牌与侧栏布局为视觉依据，保留清楚的操作反馈、可读字号和触控尺寸。参考稿未覆盖的房间、联机与恢复状态沿用同一视觉风格。
- 参考稿是视觉与交互依据；其中电脑固定不叫、简化计分及页面内模拟状态不作为业务实现依据。按正式规格补齐加倍、再加倍、身份隔离、持久化和恢复；主题切换不新增为必做范围。
